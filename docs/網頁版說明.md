# 網頁版說明

同一份程式可以產生網頁版，用手機或電腦的瀏覽器打開就能測驗，不用安裝 Expo Go。

## 網頁版和 App 的差別

| 項目 | App | 網頁版 |
| --- | --- | --- |
| 手繪畫鐘 | WebView 畫布 | 瀏覽器內建畫布（`components/DrawingCanvas.web.js`），滑鼠、手指、觸控筆都能畫 |
| 拍照模式 | 相機或相簿 | 手機瀏覽器可以拍照或選圖；電腦只能選圖片檔 |
| 連線測驗 | 手指拖曳 | 手指或滑鼠拖曳 |
| 雲端輔助辨識 | 可開啟 | **預設不提供**（網頁的程式碼公開，金鑰會外流） |
| 受測者與紀錄 | 存在手機 | 存在**這個瀏覽器**；換瀏覽器、無痕模式、清除瀏覽資料都會不見 |

辨識和評分在兩邊是同一套程式，結果一樣。

## 產生網頁檔案

在專案資料夾執行：

```
npm run build:web
```

完成後網頁檔案在 `dist` 資料夾。這個指令刻意不讀 `.env.local`，產生完還會檢查 `dist` 裡面沒有 Google 金鑰；如果出現警告，**不要上傳**。

不要直接用 `npx expo export`，那樣可能把 `.env.local` 的金鑰包進網頁裡。

## 上傳到網站空間（擇一）

### 方法一：Netlify（最簡單，拖曳上傳）

1. 到 netlify.com 註冊免費帳號。
2. 進入「Sites」頁面，把整個 `dist` 資料夾拖進上傳區。
3. 等幾秒就會得到一個 `https://xxxx.netlify.app` 網址，可以在網站設定裡改成好記的名字。
4. 之後更新：重新執行 `npm run build:web`，再把新的 `dist` 拖進同一個網站的「Deploys」頁面。

### 方法二：GitHub Pages（自動發布）

設定檔 `deploy-web.yml` 放好之後，每次把程式 push 到 GitHub，就會自動跑測試、產生網頁（不含金鑰）並發布。網址是 `https://你的帳號.github.io/專案名稱/`，網址多一層資料夾的問題會自動處理（`app.config.js` + `EXPO_BASE_URL`）。

第一次設定：

0. **放好自動發布設定檔**（只要做一次）：把 `docs/github/deploy-web.yml` 複製到 `.github/workflows/deploy-web.yml`（`.github` 和 `workflows` 資料夾要自己建立）。在專案資料夾的命令提示字元可以這樣做：
   ```
   mkdir .github\workflows
   copy docs\github\deploy-web.yml .github\workflows\
   ```
1. **更新套件清單**（只要做一次）：在專案資料夾執行 `npx expo install @react-native-async-storage/async-storage`，讓 `package-lock.json` 也記錄這個套件。GitHub 是照 `package-lock.json` 安裝的，少了會失敗。
2. **在 GitHub 建立專案**：github.com 右上角「+」→「New repository」，名稱例如 `tagusb`，**不要**勾選新增 README。
3. **把程式推上去**：在專案資料夾執行（把「你的帳號」換掉）：
   ```
   git add .
   git commit -m "畫鐘與連線測驗 App"
   git branch -M main
   git remote add origin https://github.com/你的帳號/tagusb.git
   git push -u origin main
   ```
   第一次 push 會跳出視窗要你登入 GitHub。也可以用 GitHub Desktop 做同樣的事。
4. **開啟 Pages**：到 GitHub 專案的 Settings → Pages，「Source」選 **GitHub Actions**。
5. **等它發布**：到專案的 Actions 頁面，「發布網頁版」跑完（約 3～5 分鐘，綠色勾勾）就能打開 `https://你的帳號.github.io/tagusb/`。如果第 4 步比 push 晚做，到 Actions 頁面按「Run workflow」重跑一次。

之後每次修改，只要 `git add .`、`git commit -m "說明"`、`git push`，網站就會自動更新；測試沒過就不會發布。

注意：

- `.env.local`（金鑰）已經在 `.gitignore` 裡，不會被推上去。
- 免費帳號的 GitHub Pages 需要**公開**的專案，程式碼和 `tests/fixtures` 裡的手寫照片都會公開。學生可以申請 GitHub Student Developer Pack，私人專案也能用 Pages。

## 成果展使用建議

- 把網址做成 QR code 印在海報上，參觀者用自己的手機掃描就能直接測。
- 參觀者的資料只存在他自己的手機瀏覽器裡，不會傳到任何地方，可以放心試用。
- 拍照模式需要 https 網址才能開相機；Netlify 和 GitHub Pages 都是 https。

## 如果網頁版也要開雲端輔助

只有在 Google Cloud Console 已經把金鑰設定成「只允許你的網站網址使用」（應用程式限制選「網站」並填入網址），才建議開啟：

1. `.env.local` 加上 `EXPO_PUBLIC_ALLOW_WEB_CLOUD=1`。
2. 改用 `npx expo export --platform web` 產生（`build:web` 會刻意排除金鑰）。

即使限制了網址，金鑰還是看得到，只是別人無法從其他網站使用；也建議在 Google Cloud 設定每日用量上限。
